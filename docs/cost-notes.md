# AI API 비용 구조 및 최적화 (2026-07-22)

## 결론 먼저

1. **다른 회사 "무료" API로 갈아타는 것은 권장하지 않음.** 웹 검색 도구(Recipe Scout), 이미지/URL에서 레시피 추출(Recipe Parser) 둘 다 특정 provider의 기능(Anthropic web_search 서버 도구, 비전 입력, 구조화된 JSON 출력 품질)에 묶여 있어서 갈아타면 재구현 비용 + 품질 저하 리스크가 큼. "무료" tier들은 실제로는 요청 수/토큰 제한이 낮아서 사용자가 늘면 결국 유료로 전환해야 하고, 그 시점에 다시 마이그레이션 비용이 발생함. 지금처럼 사용자 수가 아직 적을 때 provider를 바꾸는 리스크를 감수할 이유가 없음.
2. **Claude(Haiku 4.5)를 계속 쓰되, 아래 최적화로 실질 비용을 크게 줄임.** 아래는 실측 기반 수학.

## 비용이 어디서 나가는가 (Recipe Scout 검색 1건 기준)

Haiku 4.5 가격: 입력 $1/MTok, 출력 $5/MTok. `web_search` 서버 도구는 검색 1회당 별도 과금(~$0.01/search).

변경 전(`max_uses: 4`) 실측값 — 쿼리 "garlic butter shrimp pasta":

| 항목 | 값 | 비용 |
|---|---|---|
| 입력 토큰 | 2,751 | $0.00275 |
| 출력 토큰 | 1,348 | $0.00674 |
| 검색 횟수 | 3회 | $0.03 |
| **합계** | | **≈ $0.0395** |

검색 수수료가 전체 비용의 **약 76%**를 차지. 토큰을 아무리 줄여도 검색 횟수를 줄이지 않으면 비용은 거의 그대로임 — 여기가 지렛대(leverage)가 가장 큰 지점.

## 적용한 변경: `max_uses: 4` → `2`

같은 쿼리로 재측정한 결과 (`lib/ai/recipeSearch.ts`의 `max_uses` 캡을 2로 낮춘 뒤):

| 쿼리 | 검색 횟수 | 입력 | 출력 | 결과 개수 |
|---|---|---|---|---|
| garlic butter shrimp pasta (변경 전) | 3 | 2,751 | 1,348 | — |
| garlic butter shrimp pasta (변경 후) | 1 | 2,744 | 1,069 | 7개, 품질 동일 |
| kimchi fried rice (변경 후) | 1 | 2,742 | 812 | 6개, 품질 동일 |

결과 품질(추천 레시피 5~7개, `recommended` 표시)은 그대로 유지되면서 검색 횟수는 3회 → 1회로 줄었음. 비용으로 환산하면:

- 변경 전: $0.0395/call
- 변경 후: ≈ $0.00274(입력) + $0.00535(출력) + $0.01(검색 1회) ≈ **$0.0181/call**
- **건당 약 54% 절감**

## 캐싱으로 추가 절감 (이미 배포됨)

`lib/searchCache.ts` — 동일 쿼리(정규화 후 해시)는 3일 TTL 동안 캐시에서 즉시 응답, API 호출 자체가 발생하지 않음(비용 $0). 인기 검색어("파스타", "김치볶음밥" 등)는 반복 조회가 많을수록 캐시 적중률이 올라가서 실질 평균 비용은 위 $0.0181보다 더 낮아짐. 레시피 추출(`lib/ai/recipeCache.ts`)도 동일한 방식으로 이미 적용되어 있음.

**주의:** 캐시 테이블(`search_cache`)이 실제 Supabase 프로젝트에 아직 생성되지 않았다면 캐싱이 동작하지 않고 매번 API를 호출함 — `supabase/schema_07_search_cache.sql`을 Supabase SQL Editor에서 한 번 실행해야 함.

## 사용자 수가 늘어날 때의 전망

- 캐시 미적중 시에도 건당 $0.018 수준이면, 월 10,000회 검색이 발생해도 실비용은 약 $180 수준(캐시 적중률 반영 시 훨씬 낮음).
- 검색 결과 개수를 더 줄이거나(예: 5~7 → 5) 캐시 TTL을 늘리는 것도 추가 레버지만, 현재 설정으로도 품질 저하 없이 실질적인 절감을 확인했으므로 우선 이 상태로 운영하고, 실사용 트래픽 데이터가 쌓이면 다시 조정하는 것을 권장.
